# 브루 자동화 파이프라인 실행

사용자가 브루에서 대본 → TTS 음성까지 만들어 저장한 .vrew 파일을 받아,
`E:\자동화 프로그램\VREW\vrew_tool.py` 도구로 나머지 편집을 전부 자동 처리한다.
사용자는 비개발자이므로 결과 보고는 쉬운 한국어로, 기술 용어 없이 한다.

## 1단계: 입력 파일 3가지 찾기

### .vrew 파일
- 사용자가 경로를 줬으면 그것을 쓴다.
- 안 줬으면 아래 **두 폴더를 모두** 뒤져서 가장 최근에 수정된 `*.vrew`를 쓴다.
  (사용자가 처리할 파일을 넣어두는 전용 폴더. 이름이 비슷한 폴더가 둘 다 실제로 존재한다)
  1. `E:\자동화 프로그램\해줘 폴더`  ← **띄어쓰기 + "폴더"가 붙은 쪽이 실제 사용 중인 폴더다 (2026-08-31 확인)**
  2. `E:\자동화 프로그램\해줘`  ← 비어 있는 경우가 많지만 같이 확인한다
  ⚠️ 1번만 보거나 2번만 보면 파일을 놓친다. 둘 다 본 뒤 수정 시각이 최신인 것을 고른다.
- 두 폴더 모두 비어 있으면 `C:\Users\louki\Downloads`에서 최근 `*.vrew`를 찾는다.
- 이름이 `_자동화.vrew`로 끝나는 파일은 이미 처리된 결과물이므로 항상 제외한다
  (같은 파일을 두 번 처리하는 실수 방지).
- 어떤 파일을 골랐는지 반드시 사용자에게 알린다 (잘못 골랐으면 바로잡을 수 있게).

### 매칭표 (씬별_대본매칭.txt 또는 06_scene-mapping.txt)
- `E:\Channel1\output\` 아래 회차 폴더들에서 매칭표를 찾는다.
  파일명은 두 가지 중 하나다: `씬별_대본매칭.txt`(구버전) 또는 `06_scene-mapping.txt`(신버전).
  한 폴더에 둘 다 있으면 `06_scene-mapping.txt`를 쓴다
  (경제 대본 스킬이 직접 생성·갱신하는 원본이라 복사본보다 항상 최신이다).

⚠️ **폴더 이름 규칙이 2026-09-02에 바뀌었다.** 두 형식이 섞여 있으니 둘 다 처리한다.
  - 신규: `M.D-no.N` — 예 `9.2-no.1`, `9.2-no.2` (**주제어가 폴더명에 없다**)
  - 구버전: `YYYY-MM-DD_주제슬러그` — 예 `2026-08-31_중국-평균의함정-사라진일자리`

**폴더 고르는 순서 (위에서부터 시도한다)**

1. **사용자가 회차를 말한 경우** — `9.2-no.1`, `no.1`, `9월 2일 1번`, `어제 1번` 같은 표현은
   신규 폴더명과 직접 대조한다. 이게 가장 확실하므로 항상 먼저 시도한다.
2. **사용자가 주제를 말한 경우**("헝다 편이야", "베트남 편") — 신규 폴더는 이름에 주제어가 없으므로
   **각 폴더의 `_HANDOFF.md` 첫 줄**을 읽어서 대조한다. 형식은 다음과 같다:
   `# 🔄 작업 인수인계 — 9.2-no.1 (중국 공장 이탈 · 계산서는 중국으로 편)`
   `_HANDOFF.md`가 없는 오래된 폴더는 폴더명으로 대조한다.
3. **아무 말도 없는 경우** — `.vrew` 파일명의 키워드를 위 1·2번 순서로 대조한다.
4. **그래도 못 정하면** — 가장 최근에 수정된 폴더를 쓴다.

⛔ **같은 날짜 접두사가 여럿이면(`9.2-no.1`과 `9.2-no.2`가 동시에 존재) 추측하지 말고 반드시 사용자에게 물어본다.**
   "9.2 편"이라고만 하면 어느 쪽인지 알 수 없다. 회차 번호까지 확인한다.

- 어떤 폴더를 골랐는지, 그리고 그 폴더의 주제가 무엇인지 **반드시 사용자에게 먼저 알린다**
  (예: "9.2-no.1 중국 공장 이탈 편 매칭표를 씁니다"). 잘못 골랐으면 사용자가 바로잡을 수 있게.

### 그림/영상 폴더
- `E:\탄탄한 소리경제학\` 아래를 **하위 폴더까지 재귀적으로**(2~3단계 깊이) 뒤져서,
  **씬 번호 붙은 그림(scene_NN.jpg, 씬N.jpg 등)이 들어있는 폴더 가운데
  그 그림들이 가장 최근에 만들어진 폴더**를 고른다.
  예: `E:\탄탄한 소리경제학\소리경제학-8월 영상\중국 헝다그룹 회장 전재산 몰수`
  사용자가 폴더 이름과 위치를 수시로 바꾸므로 경로·이름 일치에 의존하지 않는다.
  (이름에 주제 키워드가 겹치면 참고만 한다. 후보가 둘 이상 비슷하면 사용자에게 물어본다.)
- `씬N.mp4` 영상이 있으면 해당 씬은 그림 대신 영상(최대화·음소거)이 들어간다.

후보가 여러 개라 확신이 없으면 추측으로 진행하지 말고 사용자에게 짧게 물어본다.
매칭표나 그림 폴더를 못 찾으면: 그림 배치는 빼고 나머지만 실행한 뒤, 뭘 못 찾았는지 알려준다.

## 1.5단계: 픽셀스 스톡 영상 준비 (기본 실행 — 브루 처리에 항상 포함)

사용자 방침: 전체 씬의 **35%는 픽셀스 스톡 실사 영상**, 나머지는 사용자가 만든
이미지·영상으로 채운다. "스톡 빼줘"라고 하면 이 단계를 건너뛰고,
"스톡 20%로"처럼 비율을 말하면 그 비율을 따른다.

1. 매칭표의 씬 수 N에서 목표 개수 = round(N × 0.35)를 구한다.
2. 씬 우선순위 (스톡을 넣지 않는 씬):
   - 그림 폴더에 이미 있는 `씬N.mp4`(사용자가 만든 영상)는 절대 건드리지 않고 그대로 둔다.
   - 남은 씬들 중 ▶ 이미지 설명이 **실사 촬영에 어울리는 씬**을 목표 개수만큼 고른다
     (도시 풍경·거리·공사장·군중·사무실·항구·야경 등 ⭕ / 초현실·비유·일러스트
     전용 장면(장부에서 글씨가 날아가는 등)은 사용자 이미지 유지).
     실사에 어울리는 씬이 목표보다 적으면 어울리는 만큼만 넣는다 (억지로 채우지 않음).
3. 고른 씬마다 ▶ 이미지 설명을 구체적 영어 검색어로 바꿔 내려받는다:
   `python "E:\자동화 프로그램\VREW\vrew_tool.py" --stock "<영어 검색어>" "<그림폴더>\씬N.mp4"`
   - 결과가 없으면 검색어를 더 일반적으로 바꿔 1회 재시도, 그래도 없으면 그 씬은
     사용자 이미지로 두고 넘어간다.
   - 다운로드 수가 많으면 시간이 몇 분 걸리고 결과 .vrew 용량이 커진다는 것을
     시작 전에 사용자에게 한 줄로 알려준다.
4. API 키: `E:\자동화 프로그램\VREW\pexels_api_key.txt` (등록됨, 무료 한도 월 2만 회).

## 2단계: 실행

```
python "E:\자동화 프로그램\VREW\vrew_tool.py" "<vrew 경로>" --scenes "<매칭표 경로>" --images "<그림 폴더>"
```

- 그림 배치를 뺄 때는 `--scenes`/`--images` 없이 실행한다.
- 결과물은 원본과 같은 폴더에 4개가 생긴다 (원본은 그대로 둠).
  - `<이름>_자동화.vrew` — 편집 완료된 브루 파일
  - `<이름>_음성검수.txt` — 발음 위험 구간
  - `<이름>_타임라인.txt` — **실측 타임코드** (2026-08-31 추가)
  - `<이름>_배치위치.txt` — **그림·영상이 들어간 최종 클립 번호** (2026-09-03 추가;
    클립 나누기 이후 번호라 브루 화면의 클립 번호와 일치한다)
- 실행 로그 끝에 "자체 검증(무결성): 통과 ✓"가 나와야 정상이다.
- ⚠️ 로그에서 반드시 확인할 것: `씬 시작 위치: N/N개 찾음`의 **분모와 분자가 같아야** 한다.
  다르면 그림이 빠진 채로 나온다.

## 3단계: 결과 보고

아래 내용을 쉬운 말로 짧게 정리해서 알려준다:
- 그림 몇 장 / 영상 몇 개가 배치됐는지
- 클립이 몇 개에서 몇 개로 나뉘었는지
- 한글 숫자가 몇 건 변환됐는지 (자막만 바뀌고 음성은 그대로라는 점)
- **영상 총 길이와 챕터 타임코드** — `_타임라인.txt`의 "유튜브 설명란 복사용" 블록을 그대로 보여준다.
  이건 브루 파일에서 실측한 값이라 렌더링 결과와 일치한다.
  `04_upload-info.md`의 타임코드는 대본 자수 기준 **추정치**라 4분 넘게 어긋난 적이 있다 → 실측값으로 교체하라고 안내한다.
- **영상이 들어간 클립 번호 표 (필수, 사용자가 묻기 전에 항상)** —
  `_배치위치.txt`의 "[영상이 들어간 씬]" 블록을 표(클립 번호 | 타임코드 | 씬 | 파일 | 시작 자막)로
  그대로 보여준다. 사용자가 브루에서 스톡·씬 영상을 검수할 때 클립 번호로 바로 찾아가기 위함이다
  (2026-09-03 사용자 요청: "스톡 어디 넣었어?"라고 묻지 않게 해달라).
  그림 배치 위치는 파일에 있다고 경로만 안내한다 (수십 줄이라 표로 다 보여주면 오히려 못 읽는다).
- 완성 파일 경로 — "브루에서 이 파일을 여세요"라고 안내
- 로그에 ⚠ 경고가 있었으면 그대로 전달 (예: 시작 문장을 못 찾은 씬 번호)
- **"씬 번호가 없어 건너뛴 파일" 목록이 로그에 있으면 그대로 보여준다** — 그림 폴더에
  `Video 12.mp4`처럼 무관한 번호 파일이 섞이면 엉뚱한 씬에 들어갈 뻔한 사고가 실제로 있었다
  (2026-09-03, 도구에 방지 로직을 넣었지만 건너뛴 파일은 사용자가 알아야 정리한다).

### 타임라인 리포트 동작 방식
- 챕터 목록은 `--scenes`로 준 매칭표와 **같은 폴더의 `04_upload-info.md`**에서 자동으로 읽는다.
  다른 곳에 있으면 `--chapters "<경로>"`로 지정한다. 빼려면 `--no-timeline`.
- 업로드 정보에 `0:00 소제목 - 시작 문장` 형식(편집용 블록)이 있어야 챕터별 실측이 된다.
  `0:00 소제목`만 있는 구형식이면 총 길이만 계산하고, 해당 챕터는 "실측 불가"로 표시한다.

## 추가 요청 대응

- **TTS용 대본 변환**: 사용자가 "대본 변환해줘", "TTS용으로 바꿔줘", "숫자 한글로 바꿔줘"라고
  하면 (브루에 넣기 **전** 단계) 대본 파일을 받아 아래를 실행한다:
  ```
  python "E:\자동화 프로그램\VREW\vrew_tool.py" --tts-script "<대본 경로(.md/.txt)>"
  ```
  대본 경로를 안 줬으면 `E:\Channel1\output\` 최신 폴더의 `03_script.md`를 쓴다.
  아라비아 숫자(213만, 35%, 5.4%, 6월…)를 한글 읽기로 바꾼 `_TTS용.txt`가 생기고,
  사용자는 그걸 브루에 붙여넣어 TTS를 만든다 → 이러면 TTS가 숫자를 잘못 읽을 수 없다.
  나중에 '브루 처리'가 자막을 다시 아라비아 숫자로 되돌린다 (음성은 그대로).

- **썸네일 검수**: 사용자가 "썸네일 검수해줘"라고 하면 썸네일 이미지 경로를 받아
  (없으면 Downloads에서 최근 이미지 확인 후 사용자에게 확인) 아래를 실행한다:
  ```
  python -c "import sys; sys.stdout.reconfigure(encoding='utf-8'); sys.path.insert(0, r'E:\자동화 프로그램\VREW'); from vrew_tool import review_thumbnail; print(review_thumbnail(r'<썸네일 경로>', r'<대본 또는 vrew 경로>', print))"
  ```
- **스톡 영상 조절**: 스톡 섞기는 1.5단계에서 기본(35%)으로 실행된다.
  "스톡 빼줘"(생략), "스톡 20%로"(비율 변경), "씬 12, 30에 스톡 넣어줘"(씬 지정)를 따른다.
  픽셀스 영상은 상업적 이용 무료·출처 표기 불필요.
- **일부 기능만**: "그림 배치만 해줘", "나누기는 빼줘" 같은 요청이면 CLI 플래그로 조절한다:
  `--no-split`(나누기 제외) `--no-numbers`(숫자 변환 제외) `--no-rules`(자막 교정 제외)
  `--no-font`(글자 크기 제외) `--no-report`(음성검수 제외) `--no-timeline`(타임라인 제외)
  `--chapters "<04_upload-info.md 경로>"`(챕터 파일 직접 지정) `--anim`(기존 그림 애니메이션 랜덤)
- 도구 자체를 고치거나 기능을 추가하는 요청이면 이 스킬 범위 밖이므로
  `E:\자동화 프로그램\VREW\vrew_tool.py`를 직접 수정한다 (메모리의 vrew-automation-project 참고).
