# 일본 캡컷 자동화 워크플로우

사용자를 대신해 이 저장소의 프로그램들을 순서대로 실행한다.
사용자는 비개발자다: 명령어·코드를 보여주지 말고, 결과를 쉬운 한국어로 요약해서 전달한다.

## 전제 조건 확인 (조용히, 빠르게)

1. 이 세션이 사용자의 **노트북(Windows, 캡컷 설치됨)** 에서 실행 중인지 확인.
   원격/클라우드 세션이면: 캡컷과 파일이 노트북에 있어서 여기서는 실행할 수 없다고
   설명하고, 노트북에서 이 폴더를 열고 다시 말해달라고 안내 후 종료.
2. `api_key.txt` 가 이 폴더에 있는지 확인. 없으면 사용자에게
   "tts_test.bat 을 한 번 실행해서 API 키를 등록해 달라"고 안내.
   **API 키를 채팅으로 붙여넣게 하지 말 것.**
3. 필요한 패키지 확인: `python -c "import PIL, openpyxl, mutagen, imageio_ffmpeg, pycapcut"`
   실패하면 `install_review.bat` 실행(또는 pip install)을 대신 해 준다.

## 1단계: 프로젝트 폴더 찾기

- 사용자가 경로를 말했으면 그것을 쓴다.
- 아니면 흔한 위치(바탕화면, 다운로드, 문서, 이 저장소 주변)에서
  "파일명에 '대본'이 들어간 .txt + images 폴더(또는 이미지 여러 장)"를 가진 폴더를 찾아,
  후보를 최근 수정순으로 보여주고 사용자에게 고르게 한다. 후보가 1개면 그걸로 진행하되 어느 폴더인지 알려준다.
- sample_project / sample_video_project 는 연습용이므로 후보에서 제외.

## 2단계: 사전 검토

```
python japan_review.py "<프로젝트폴더>" --no-open
```

- **오류가 있으면 멈춘다.** 오류 내용을 쉬운 말로 요약하고, 고칠 수 있는 것
  (예: 씬 매핑 문구 수정)은 사용자 확인을 받아 직접 고친 뒤 재검토.
- 씬 수 ≠ 이미지 수면 자동배치가 안 되므로 반드시 여기서 해결.

## 3단계: 목소리·속도 확인

- `builder_config.json` 에 지난번 목소리가 있으면:
  "지난번처럼 {voice}(으)로 할까요?" 하고 한 번만 묻는다 (기본값 = 그대로).
- 없으면 추천 6종(Charon/Gacrux/Iapetus/Kore/Sulafat/Vindemiatrix)을 한 줄씩
  설명해 주고 고르게 한다. 속도 기본값은 "느리게"(시니어 타깃).

## 4단계: 자동배치 실행

```
python video_builder.py "<프로젝트폴더>" --voice <목소리> --speed <속도>
```

- 씬이 많으면 오래 걸린다. 진행 상황(몇 번째 씬인지)을 중간중간 알려준다.
- 429(사용량 제한)로 오래 기다리면 그 사실을 알려준다. 프로그램이 알아서 재시도한다.
- 실패해도 이미 만든 씬 오디오는 남는다. 같은 명령을 다시 실행하면 이어서 한다.
- "캡컷 초안 폴더를 찾지 못했다"고 나오면: 사용자에게 캡컷 → 설정 → 초안 위치 경로를
  물어보고 `--draft-dir "<경로>"` 를 붙여 다시 실행.

## 5단계: 최종 검토와 마무리 보고

```
python japan_review.py "<프로젝트폴더>" --no-open
```

결과를 요약해서 보고한다:
- 나레이션 총 길이, 자막 개수, 캡컷 초안 이름
- 검토 리포트의 오류/주의 요약 (오류가 있으면 원인과 해결책)
- "캡컷을 열면 초안 목록에 '<이름>'이 있으니 열어서 확인 후 내보내기 하세요"
- 내보낸 mp4를 이 폴더에 넣고 다시 "검토해줘"라고 하면 동영상 내용까지 검사해준다는 안내

## 금지 사항

- api_key.txt, builder_config.json 을 채팅에 출력하거나 커밋하지 말 것.
- 사용자의 대본/이미지 파일을 임의로 수정·삭제하지 말 것 (씬 매핑 수정은 확인 후에만).
- TTS 비용이 발생하므로, 같은 씬을 불필요하게 다시 생성하지 말 것 (이어하기 활용).
